# DS-аудитор kardio

Проверяет деплой kardio на соответствие дизайн-системе Яндекс Мед (`design-system/README.md`, `design-system/tokens.json`) и выдаёт таблицу правок в формате эталона `docs/audits/2026-10-21-kardio-ds-audit.md`. Сам продукт аудитор не правит и ничего не деплоит: он только открывает страницы по HTTP.

## Как запустить локально

```bash
npm run ds:audit -- --url https://kardio-eta.vercel.app --no-ai
```

Отчёт появится в `ds-audit-output/`:
- `report.json` — машинный отчёт;
- `report.md` — таблица;
- `screenshots/` — верх каждой страницы в двух вьюпортах.

Без базы для сравнения прогон рекомендательный: все находки — `NEW`, гейт `success`.

| Флаг | Что делает |
| --- | --- |
| `--url` | Деплой, который проверяем (обязателен) |
| `--routes /a,/b` | Только эти маршруты; без флага — стандартный набор плюс ссылки навигации |
| `--no-crawl` | Не добавлять маршруты из навигации |
| `--viewports desktop,mobile` | Вьюпорты: 1440×900 и 390×844 |
| `--baseline report.json` | Сравнить с готовым отчётом |
| `--base-url <url>` | Сравнить с другим деплоем, проверив его в этом же прогоне |
| `--base-sha`, `--commit-sha` | SHA для отчёта и для поиска базы в `--state-dir` |
| `--state-dir .ds-audit-state` | Каталог состояния, как в CI |
| `--mode baseline --commit-sha <sha> --state-dir …` | Сохранить отчёт как базовый для коммита |
| `--fail-on-gate` | Код выхода 1, если гейт `failure` |
| `--no-ai` | Смысловой слой не запускать. В v1 он выключен всегда, флаг оставлен для совместимости |

Пример регрессионной проверки двух деплоев:

```bash
npm run ds:audit -- --url https://<превью>.vercel.app --base-url https://kardio-eta.vercel.app --no-ai --fail-on-gate
```

## Проверки

```bash
npm run ds:audit:typecheck
npm run ds:audit:test
```

`ds:audit:test` запускает Chromium на HTML-фикстурах из `__fixtures__/`: по «плохому» и «хорошему» примеру на каждое правило. Тесты также проверяют регрессионный гейт, NEW / EXISTING / FIXED и стабильность отпечатков.

## Правила

| ID | Проверка | Блокирует |
| --- | --- | --- |
| R-00 | Страница загружается (HTTP < 400, без таймаута) | Да |
| R-01 | Цвет текста и фона под текстом — из палитры `tokens.json` | Да |
| R-02 | Контраст ≥ 4,5:1 (крупный текст ≥ 3:1). Белая подпись основной кнопки на `accent`, 14 px / 600 — предупреждение | Да |
| R-03 | `line-height / font-size` ≥ 1,2 | Да |
| R-04 | Кегль ≥ 11 px | Да |
| R-05 | Зона нажатия ≥ 44×44 на 390 px; ссылки внутри `p` и `li` не считаются | Да |
| R-06 | axe-core (wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa): 0 serious/critical. `color-contrast` исключён: это R-02 | Да |
| R-07 | Ровно один `h1`, уровни заголовков без пропусков | Да |
| R-08 | `© <год> ООО «Яндекс»` на каждой странице | Да |
| R-09 | Запрещённые строки — `banned-copy.ts` | Да |
| R-10 | Неразрывные пробелы в заголовках и резюме | Нет |
| R-11 | `:root` совпадает с `tokens.json`; нет `var(--color-`; нет литералов цвета вне `:root`, кроме иллюстраций `.fa-*`. Токен `--ws-*`, которого нет в DS, — предупреждение | Да |
| R-12 | Нет терминов другой специальности — `specialty-lexicon.ts` | Да |
| R-13 | Видимый фокус: сплошная обводка ≥ 2 px на элементе или у контейнера с `:focus-within` | Да |

R-13 нет в таблице TASK.md. Оно добавлено, чтобы детерминированный слой воспроизводил эталонную находку DS-08.

Аудит детерминирован:
- страницы открываются по событию `load`, затем ждём шрифты и паузу;
- `reducedMotion: reduce`;
- одна страница за раз;
- без времени и координат в находках.

## Регрессионный гейт

- **Fingerprint** = `rule_id:sha256(rule_id, identityVersion, маршрут, вьюпорт, локатор, ключ нарушения)`.
  - **Локатор:** ближайший стабильный якорь (`id`, `data-agent`, landmark с `aria-label`), тег и классы без `is-*`/`has-*`. Для правил про тексты добавляется нормализованный текст.
  - **Измеренные величины** (размеры, контраст, количество) в отпечаток не входят. Частичная правка или перестройка вёрстки оставляют находку той же.
  - **Домен деплоя** в отпечаток не входит. Превью и прод сравниваются напрямую.
- **NEW** — есть в прогоне, нет в базе. **EXISTING** — есть и там, и там. **FIXED** — была в базе, пропала, и страница проверена в этом прогоне. Находки базы на непроверенных страницах считаются в `not_compared`.
- **Gate `failure`** — только при NEW детерминированной находке с `blocking: true`. EXISTING, предупреждения (R-10 и др.) и смысловые находки не блокируют.
- **Базы нет** (`baseline_status: unavailable`) — прогон рекомендательный, статус `success`.

## CI

Workflow: `.github/workflows/ds-audit.yml`.

- **`repository_dispatch: vercel.deployment.success`, окружение `preview`.** Ищет открытый PR, у которого head — этот коммит. Считает `base_sha` как merge-base с основной веткой. Берёт базу и публикует:
  - один комментарий в PR (по маркеру `<!-- ds-audit -->`);
  - commit status `ds-audit/regression` на head SHA.
- **`repository_dispatch`, окружение `production` из основной ветки.** Сохраняет базовый отчёт и URL деплоя для этого коммита. Не комментирует.
- **`workflow_dispatch`** — ручной запуск:
  - `mode=manual` — с `pr_number` комментирует и ставит статус;
  - `mode=baseline` с `sha` — засевает базу;
  - `mode=deep` — полный прогон; смысловой слой в v1 выключен.

**Порядок поиска базы:**
1. Сохранённый отчёт для `base_sha` той же версии аудитора и правил.
2. Повторная проверка известного деплоя `base_sha`.
3. `unavailable`.

**Состояние** (`.ds-audit-state/`) переживает раннер через GitHub Actions cache:
- в начале — `restore` самого свежего снимка по префиксу `ds-audit-state-v1-`;
- в конце — `save` под уникальным ключом рана.

Записи адресуются по SHA или содержимому. Поэтому потерянная запись приводит только к повторному расчёту, а не к неверному сравнению. Записи без обращений 30 дней и сверх 50 МБ удаляются.

**Права workflow:** `contents: read`, `pull-requests: write`, `statuses: write`. Секреты не нужны, кроме встроенного `GITHUB_TOKEN`.

**Переменные репозитория** (необязательные):
- `DS_AUDIT_VERCEL_PROJECT` (по умолчанию `kardio`);
- `VERCEL_PROJECT_ID` — для проверки payload.

## Как добавить правило

1. Создайте `rules/rNN-<что>.ts` с объектом `Rule`:
   - `id`, `priority`, `blocking`;
   - тексты `rule` / `fix` / `check`;
   - функция `run(ctx)`. Она получает снимки страниц и возвращает `RawFinding[]` с `locator` и `evidenceKey`.
2. Добавьте правило в `rules/index.ts` и поднимите `RULESET_SEMVER`.
3. Если правилу нужны новые данные со страницы, соберите их в `collect/in-page.js` (чистый JS, выполняется в браузере) и добавьте тип в `types.ts`.
4. Добавьте `__fixtures__/rNN-bad.html` и `rNN-good.html` и строку в `CASES` в `__tests__/rules.test.ts`.
5. **`identityVersion`** меняйте только тогда, когда меняется, что считается «той же находкой». Отпечатки правила изменятся, и прежние находки станут FIXED, а новые — NEW.

Запрещённые строки — в `banned-copy.ts`, словари специальностей — в `specialty-lexicon.ts`. `id` паттерна или термина входит в отпечаток: не переименовывайте его без нужды.

## Как обновить токены

1. Обновите `design-system/tokens.json` (и `README.md`, если изменились правила).
2. `ds_version` изменится сам: это `version` из `tokens.json` плюс хеш обоих файлов.
3. Сопоставление имён `tokens.json` → CSS — в `tokens.ts`:
   - цвет, отступы, радиусы, тени, раскладка → `--ws-<name>`;
   - кегль → `--font-size-<style>`;
   - интервал → `--ws-leading-<style>` (оба `display-*` → `--ws-leading-display`);
   - трекинг → `--ws-tracking-<style>`;
   - `sans` → `--font-sans`.
4. Фикстуры получают `:root` из `tokens.json` автоматически. Прогоните `npm run ds:audit:test`.

## Смысловой слой (v1: подготовлен, выключен)

В `semantic/` лежат режимы `pr` и `deep`, промпт, JSON-схема, фильтр фактов и ключ кеша по содержимому страницы. В v1 Anthropic API не вызывается, ключ не нужен, в отчёте `semantic.mode: "skipped"`.

Перед включением нужно:
- сверить ID модели, параметр рассуждений и цены по документации Claude API;
- подключить клиент в `semantic/run.ts`;
- задать `ANTHROPIC_API_KEY` и бюджеты `DS_AUDIT_PR_BUDGET_USD` / `DS_AUDIT_DEEP_BUDGET_USD`.

Режим `deep` с максимальным уровнем рассуждений запускается только вручную.
