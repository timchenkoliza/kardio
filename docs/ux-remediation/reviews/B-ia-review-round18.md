## Новые дефекты

### N18-01 · P1 · регрессия e8b6507 · главная молча считает учтённой латиницу, которой нет в её запросе
1. **Место.**
   - `latinInQuery` (`lib/portal/unmatched.ts:154`) берёт шаблон разбора `[A-Za-z][A-Za-z0-9\- ]{2,}`, который ловит «AF », «QT », «ST ».
   - Используется по умолчанию и в `SearchConditions` (`components/experience/experience-view.tsx:235`).
   - Запрос главной строится по `latinTermsIn` (`lib/portal/lexicon.ts:239`; `server/mesh/sources/pubmed.ts:170`): только слова от 3 букв и не больше 4.
2. **Путь сейчас.** Врач вводит вопрос в поле на главной (это задача «Ответ по источникам»), `latin-home-*.txt`:
   - «AF у пожилых» → запрос `(elderly OR older OR aged)` → «Искали по: пожилые пациенты», «Не учтено» пусто;
   - то же для «HF у пожилых», «MI у пожилых», «PE у пожилых»;
   - «QT interval при ФП» → в запросе только «interval», «Не учтено» пусто;
   - «Депрессия сегмента ST при ИБС» → «депрессия сегмента», «ST» молча;
   - «NYHA II при ХСН» → «II» молча;
   - «Витамин D3 при ХСН» → «витамин», «D3» молча.

   На dd682a7 всё это было названо. «Коротко» показывает выводы по пожилым вообще, и о потере предмета вопроса не сказано ничего. Это тот же класс, что N16-1 (A, P1). Тест e8b6507 «ХСН NYHA II–III» закрепляет именно это поведение.
3. **Структура.** «Учтено» означает «есть в фактическом запросе этого пути»:
   - разбор передаёт свою латиницу;
   - главная передаёт `intent.entities.latin`, то есть `latinTermsIn`, с тем же лимитом в 4 слова.
4. **Названия** без изменений.
5. **Переходы** без изменений.
6. **Что переиспользовать.** Параметр `options` у `unmatchedWords` (там уже есть `latinSearched`); `latinTermsIn`.
7. **Критерий.**
   - На главной «AF у пожилых», «QT interval при ФП», «HF у пожилых», «Витамин D3 при ХСН», «Депрессия сегмента ST при ИБС» называют «AF», «QT», «HF», «витамин D3», «депрессия сегмента ST».
   - В разборе с PubMed они по-прежнему учтены.
   - «Beta blockers in heart failure» и «Lp(a)» на главной — «Не учтено» пусто.
