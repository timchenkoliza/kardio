## P0 — врач получает неверный или вводящий в заблуждение результат

### A-01 · P0 · «Кратко» запускает новый поиск по теме, а не сокращает материал

**Где.** Главная `/cardiology`, лента «Для вас» и страница материала `/cardiology/item/[id]`.
- Метка задаётся в `server/portal/for-you.ts:123`, функция `scenariosFor`: `{ label: "Кратко", job: "answer", text: topic }`.
- Нажатие обрабатывает `components/portal/scenario-buttons.tsx`: `command ask` и затем `router.push(redirect)`.
- Подпись к кнопкам — в `app/[specialty]/(workspace)/item/[id]/page.tsx:88`.

**Шаги.** Главная → в первой карточке нажать «Кратко →». Или открыть карточку → на странице материала нажать главную синюю кнопку «Кратко».

**Что происходит (по коду, совпадает со скриншотом feed-item и с UX-09 у команды):**
- создаётся новый прогон «Ответ по источникам» по теме карточки, например «Запрос: «митральный клапан»»;
- открывается другая страница `/ask?run=…`;
- подпись под кнопками обещает обратное: «Агенты разберут тему «митральный клапан» по источникам — ответ откроется здесь же»;
- первый блок нового ответа называется «Коротко», что ещё сильнее путает «Кратко о статье» и «коротко о теме».

**Почему не работает.**
- Метка обещает действие над текущим объектом, а делает поиск по другому объекту. Это ломает предсказуемость.
- Материал, который врач читал, пропадает с экрана, а в результате нет пути назад к нему (см. A-09).

**Как устроить взаимодействие.**
- Сам материал уже и есть короткая версия: «Ключевая мысль» плюс основной результат.
- Действия «по теме» — вторичные, и в подписи прямо названо, что они запускают: «Исследования по теме «митральный клапан»», «Рекомендации по теме «…»».
- Если «Кратко» нужно, это раскрытие на месте (disclosure) без запроса к серверу.

**Минимальное изменение.**
1. Убрать «Кратко» из `scenariosFor`.
2. На странице материала переименовать две оставшиеся кнопки, вписав тему в подпись.
3. Исправить строку «откроется здесь же» на «откроется новый результат».

**Критерий приёмки.**
- Ни на карточке, ни на `/item/*` нет элемента с подписью «Кратко», который отправляет `POST /api/agents {action:"ask"}`.
- Любая кнопка, запускающая поиск, содержит в подписи тему поиска.
- После раскрытия краткой версии URL не меняется.

**Подтверждает:** замечания 6 и 7; UX-09.

**Как устроить взаимодействие.**
1. Первая строка — статус ответа: «Прямой ответ в N источниках» или «Прямого ответа не нашлось — вот что есть шире вопроса».
2. Дальше 1–3 утверждения, которые отвечают на вопрос и его условия. Для «противопоказаний» и «безопасности» сначала нужный раздел инструкции.
3. Две **разные** метки: «по вопросу / шире вопроса» и «цитата сверена».
4. Текст вывода виден без клика: дословно и с пометкой языка.

**Минимальное изменение.**
- В `takeawayClaims` исключать кандидатов с `onTopic === 0`, если у вопроса есть термины. Если никого не осталось — показывать «Прямого ответа не нашлось».
- Для семейства drug ставить вперёд вид утверждения, названный в вопросе (`contraindication`/`warning` по словам «противопоказ», «безопасн»). Регулярные выражения уже есть в `lib/mesh/refine.ts`, `FOCUS`.
- Переименовать «Подтверждено источником» в «Цитата сверена».
- Не сворачивать цитату внутри «Коротко».

**Критерий приёмки.**

- На «Аторвастатин: противопоказания» первый пункт «Коротко» — противопоказание, а показаний в «Коротко» нет.
- Метка «сверено» нигде не стоит без метки соответствия вопросу.
- На 390 первое предложение ответа видно в первом экране после заголовка.

**Не проверено.** Запрос «Аторвастатин: противопоказания» живьём не прогоняла. Механизм тот же, что в кейсе апиксабана.

### A-03 · P0 · Пустой результат выдан за готовый: «не искали», «не нашли» и «ошибка источника» выглядят одинаково

**Где.** `/cardiology/ask?run=…`.
- Статус прогона: `components/workspace/run-trace.tsx`, строки 7 и 18. `completed` всегда «Готово», счётчик «0 находок».
- Шаг «Собрали ответ из источников» всегда со статусом `done`: `server/mesh/executor.ts:330`.
- Без терминов PubMed вообще не вызывается, но исход записывается как `outcome:"empty"` («ничего не нашлось»): `server/mesh/sources/pubmed.ts:160`.
- Главный текст одинаков при любом исходе, если документов 0: `components/experience/experience-view.tsx:455` (`Notices`) и `components/portal/job-results.tsx:146`.

**Шаги.** Ввести «???» и отправить. Подтверждено скриншотами b.pdf.png (production) и answer-unrecognised-390/1440.

**Что видно.**
- «Подходящих источников не нашлось. Назовите заболевание… «метформин при ХБП» или «профилактика мигрени»». Примеры не кардиологические.
- В раскрытии «Как искали»: «Готово · 0.0 с · 0 находок», зелёная галочка «Разобрали запрос — Тема не распознана», зелёная галочка «Собрали ответ из источников — 0 выдержек».

**Почему не работает.**
- Система знала, что тема не распознана, и всё равно прошла весь путь и показала «Готово».
- Главная фраза говорит «не нашлось», будто поиск был, хотя его не было.
- **По коду** то же самое произойдёт, если PubMed недоступен: первая строка та же «не нашлось — переформулируйте», а причина есть только в серой строке «Чего не хватает» и в свёрнутом списке источников.
- Врач может решить, что данных нет, хотя упал источник. Это UX-10.

**Как устроить взаимодействие.** Четыре различимых состояния в первой строке результата:
- «Нашли»;
- «Искали в: … — ничего подходящего»;
- «Не искали: не распознали тему» плюс варианты уточнения;
- «Источник не ответил» плюс «Повторить».

Галочки ставить только у шагов, которые реально что-то дали.

**Минимальное изменение.**
1. Если маршрут `vague` и нет ни понятий, ни латиницы, показывать существующий блок уточнения `pt-clarify` до запуска, а не создавать прогон.
2. В `RunTrace` при `resultIds.length === 0` писать «Нет результата», а не «Готово».
3. В `Notices` выбирать текст по исходам источников (`not_invoked` / `empty` / `failed` / `unavailable`).
4. Примеры брать из `SUGGESTIONS[specialty]`.

**Критерий приёмки.**
- «???» не даёт страницы со словом «Готово».
- На стенде с `PUBMED_DISABLED=1` общий вопрос показывает в первой строке «PubMed не ответил» и кнопку «Повторить».
- Пустой поиск называет, где искали.
- В кардиологии примеры кардиологические.

**Хорошо:** в разборе исследований эти состояния уже различаются: `lib/agents/research-answer.ts`, виды `unavailable`, `not_found`, `skipped`. Это образец.

**Подтверждает:** замечание 9; UX-07, UX-10.

  - Сравнение, «Все найденные» и экспорт свёрнуты.
  - Это образец для общего ответа.
- **Устойчивые прогоны:** страница результата переживает перезагрузку, `RunProgress` честно пишет «дольше обычного» и «нет связи», есть «Повторить».
