- **Недоступный источник.** На стенде с `PUBMED_DISABLED=1` любой запрос даёт «PubMed не ответил, разбор не выполнен», без найденного.
- **Данные пациента.** «Пациент Иванов Иван Петрович, 67 лет, разбери исследование DAPA-HF» сохраняется как «Пациент [ФИО], 67 лет…», имя не уходит в поиск.

## Что проверяем на каждом запросе

- **Главный ответ первым.** На телефоне ответ идёт сразу после заголовка, новый разбор ниже.
- **Цифры с цитатой.** Каждое число эффекта открывается цитатой «Откуда цифры» и совпадает с текстом статьи.
- **Первоисточник.** У каждой работы есть ссылка на PubMed, DOI или полный текст PMC.
- **Время.** В живом прогоне ответ занимал от 0 до 4 секунд; на preview время видно в «Как искали».
- **Ничего лишнего.** Нет декоративных картинок, нет ложного «найдено» при ошибке источника.

## Вопросы о технических ограничениях

1. Без ключа NCBI PubMed ограничивает частоту запросов. Нужен ли ключ на preview и в production до теста с врачами?
2. Извлечение параметров сделано регулярными выражениями. Покрытие на тестовом наборе пока не измерено. Кто соберёт 30–50 аннотаций с эталонной разметкой?
3. Поиск по теме ищет в PubMed только по журналам, одобренным врачами (сейчас Nat Med, Cochrane, BMJ, Lancet). Разбор по идентификатору этот фильтр не применяет.
4. Время и ошибки пишутся в `agent_run_completed` и `source_failed`. Отдельной панели для команды нет.

## Решения, которые нужны от команды

1. **Русский синтез.** Выводы авторов сейчас показываются на английском, практический вывод продукт не формулирует. Добавляем ли слой перевода или русского резюме на модели с проверкой по тексту статьи до теста с врачами, или тестируем как есть?
2. **Список журналов.** Остаётся ли список одобренных журналов жёстким фильтром поиска по теме, или становится приоритетом? Сейчас из-за фильтра вопрос про DAPA-HF не находит основную статью NEJM.
3. **Режимы ответа на главной.** Переключатель «Короткий / Полный / Режим исследования» и сценарий «Разбор по исследованиям» называют похожие вещи. Оставляем переключатель, переименовываем третий режим или убираем его с главной?

## Критерии, при которых сценарий отдаём врачам

- Все 8 запросов дают ожидаемый тип результата на preview.
- Ни одного числа без цитаты из статьи и ни одного «найдено» при недоступном источнике.
- На телефоне главный ответ виден первым, горизонтальной прокрутки нет.
- Решения 1–3 приняты или явно отложены с владельцем.
- Покрытие извлечения измерено хотя бы на 30 аннотациях, и ошибок с ложной цифрой нет.

  - Приоритет как порядок в ответе (сборка #27, браузер).
  - Профиль сохраняет настройки после перезагрузки.
  - Разная семантика «Приоритета» в разборе.
  - Дефект повторного использования доказательств (ниже).
- **Автотестами.**
  - Исключение PubMed и РКО.
  - Скрытие публикаций исключённого журнала.
  - Приоритет не меняет набор.
  - Извлечение чисел на синтетических текстах.

  - Исключение PubMed и скрытие Eur Heart J живыми запросами.
  - Работа без `NCBI_API_KEY` при частых запросах.
  - Фоновый режим «Академическая основа», экспорт, экранные дикторы.
  - Реакция врачей.

### Что блокирует тест с врачами

1. **Чужие доказательства в обычном ответе (есть в `main` и в production).** Ключ повторного использования (`server/mesh/executor.ts`, `intent.id` и исключённые источники, 6 часов, общий для всех пользователей экземпляра) не учитывает тему вопроса. «Длительность ДАТТ после ЧКВ», «Гипертрофическая кардиомиопатия: лечение», «Лечение лёгочной гипертензии» и «Профилактика инфекционного эндокардита» получают один ключ. Проверено: после вопроса о ДАТТ вопрос о ГКМП показал 5 метаанализов о тикагрелоре с пометкой «из недавно проверенных». Разбор по исследованиям этот путь не использует.
2. **Точность извлечения эффектов не измерена** на размеченном наборе.
3. **«Приоритет» значит разное** в ответе и в разборе, а профиль обещает одно.
4. **#26 и #27 проверены по отдельности;** общий preview не собирался.
