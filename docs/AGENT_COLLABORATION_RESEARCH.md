Общая оговорка: почти все результаты проектов заявлены самими авторами, и у нескольких есть расхождения кода со статьёй. Это учтено в оценке каждого паттерна.

- **AgentRxiv** — по коду: в конфигурации эксперимента `agentRxiv` не включён, параллельная ветка заканчивается `NotImplementedError`. Дата «публикации» — всегда `date.today()`. Авторы сами пишут, что часть «статей» содержит результаты, не совпадающие с экспериментом.
- **AgentNet** — по коду: «умное вытеснение» никогда не срабатывает, и память замерзает на ёмкости; найденный опыт не попадает в промпт.
- **OpenEvolve** — пример с ядрами MLX после исправления оценщика оказался на 3,2 % медленнее базового варианта, при заявленном ускорении «в 2–3 раза».
- **Robin** — анализ показал рост в 7,5 раза, ручная проверка — в 1,75 раза.

## 2. Паттерны: что решают и как устроены

| # | Паттерн | Где в референсах | Какую проблему решает | Как устроен по реализации |
| --- | --- | --- | --- | --- |
| P1 | Долговечный артефакт с происхождением и родословной | OpenEvolve `Program`, Buttercup `PatchAttempt`, AgentTeams `shared/tasks/{id}` | Результат шага можно передать дальше, сравнить, перепроверить и откатить | Запись с id, `parent_id`, поколением, промптами, метриками и артефактами (OpenEvolve). Попытка со стратегией, diff, выводом сборки и тестов, статусом и разбором неудачи (Buttercup). Папка задачи `spec.md` / `plan.md` / `result.md` + история переходов (AgentTeams) |
| P2 | Конечный автомат задачи с одной точкой перехода | AgentTeams TeamHarness, очередь отправок Buttercup в Redis | Работа переживает перезапуск, нет «зависших» состояний | `planned → … → completed / revision / blocked / cancelled`, единственная функция перехода, append-only история (не больше 50 записей) с исполнителем и временем |
| P3 | Автор отдельно от проверяющего с **детерминированной** проверкой | Aristotle (ядро Lean, запрет `sorryAx`), Buttercup (сборка + PoV + тесты), OpenEvolve (пользовательский оценщик, каскад) | Убедительный текст не принимается за правильный | Результат принимается, только если проходит исполняемую проверку. | P4 | Проверка ещё одним LLM | Virtual Lab (Scientific Critic), AgentRxiv (рецензенты), Robin (попарный судья), Buttercup (Reflection) | Дешёвая критика плана и формулировок | Критик — та же модель с другой ролью. Видит текст, а не первоисточник |
| P5 | Память отрицательных результатов | Robin («уже проверено — не предлагай»), Buttercup (разбор неудачной попытки), Aristotle (список недоказанных лемм) | Не повторять бесполезную работу | Список проверенного и неудачного передаётся в следующий шаг |
| P6 | Долговременная исследовательская память и повторное использование чужих результатов | AgentRxiv | Новая задача опирается на выполненную работу | Хранилище «статей», поиск по эмбеддингам, LLM-пересказ найденного в обзоре литературы |
| P7 | Параллельные варианты и слияние | Virtual Lab (5 встреч при температуре 0,8 → слияние при 0,2), Robin Finch, острова OpenEvolve | Разнообразие решений | Несколько прогонов одной модели, затем слияние или консенсус |
| P8 | Менеджер, исполнители и динамическая маршрутизация | AgentTeams (Manager + Workers в контейнерах), AgentNet (граф маршрутизаторов с весами) | Распределить задачу по специалистам | Выбор исполнителя по ролям, навыкам и занятости. AgentNet учится по совпадению с эталонными ответами |
| P9 | Эволюционное улучшение с оценщиком | OpenEvolve | Подбор решения при наличии измеримой цели | MAP-Elites + острова, обратная связь оценщика в промпте, контрольные точки и возобновление |

## 3. Сопоставление с текущим Kardio

Kardio уже устроен как исполняемый граф с типизированными результатами, хотя так не назывался:

**Запрос → `compileIntent` (NormalizedIntent) → `planSources` (ExecutionPlan) → `executePlan` (источники параллельно, мягкий и жёсткий дедлайн, бюджет) → `buildEvidenceGraph` → `compileExperience` (ExperienceManifest) → политики → AgentRun / AgentResult / Material.**

Модель в контуре нет: маршрутизация, извлечение и проверки детерминированы. Это решение продукта (CF-05 в матрице покрытия). Оно же главное ограничение для заимствований: всё, что требует LLM-автора или LLM-критика, здесь — новая сущность, а не доработка.

| Паттерн | Уже есть в Kardio (код) | Чего не хватает |
| --- | --- | --- |
| P1 артефакт | `EvidenceGraph` (документы с отпечатком версии, чанки с отпечатком, утверждения со статусом проверки, отношения, конфликты, свежесть, покрытие требований, пробелы) — `lib/mesh/evidence.ts`. `AgentResult` со стабильным `key`, `Evidence` + `Provenance`. `Material` с `sourceResultId`. Снимок ссылки `SharedSnapshot` | Общий «конверт»: статус жизненного цикла (черновик / проверен / отклонён / устарел / заменён), явные родители и производные, условия повторной проверки, история изменений самого результата |
| P2 конечный автомат | Жизненный цикл прогона `queued → running → partial → completed / failed / blocked` с дедлайном и истечением (`settleExpiredRun`). Журнал слотов фонового планировщика с ограниченными повторами (`server/agents/scheduler.ts`) | Этапы внутри одного разбора с собственным статусом; повтор только упавшего этапа |

## 4. Модель артефакта и графа исполнения

### 4.1 Контракт артефакта: общий конверт и типизированное содержимое

Параллельного хранилища не вводим. Конверт — набор полей поверх существующих `AgentResult`, `AgentRun`, `EvidenceGraph` и `Material`. Почти всё уже есть, новое помечено ★.

| Поле контракта | Откуда берётся сейчас | Новое |
| --- | --- | --- |
| стабильный id и тип | `AgentResult.id`, `key` (стабильная идентичность находки), `kind` | ★ `artifact.kind` для новых типов (`study_appraisal`, `search_outcome`) |
| владелец и область доступа | `sessionId` у каждой записи; `Provenance.ownership` (USER_UPLOADED / PUBLIC_SOURCE / PARTNER_SOURCE / GENERATED) | — |
| исходная задача и родители | `AgentResult.runId`; `Material.sourceResultId` | ★ `artifact.parents: string[]` (id артефактов-входов), ★ `artifact.derived` вычисляется обратным индексом |
| версия и статус | `DocumentVersion.fingerprint`; `verificationStatus` у каждого утверждения | ★ `artifact.version` (номер), ★ `artifact.status`: `draft` \| `verified` \| `rejected` \| `stale` \| `superseded` |
| исполнитель и инструменты | `AgentRun.agentId`, `plan[]`, `toolsUsed[]` (инструмент, коннекторы, режим, статус, длительность) | — |
| первоисточники и версии данных | `Evidence.sourceUrl`, `Provenance`, `GraphDocument.version` | ★ `artifact.sourceFingerprints` — отпечаток текста, из которого извлекали |
| входные параметры и ограничения | `AgentRun.input` (текст, режим ответа), `ctx.preference.excludedSources`, `evidenceReuseKey` | ★ `artifact.constraints` — снимок исключённых и приоритетных источников |
| время создания и проверки | `createdAt`, `retrievedAt` | ★ `artifact.verifiedAt` |
| подтверждённое и неизвестное | утверждения со статусом SUPPORTED / PARTIALLY_SUPPORTED / UNKNOWN; `graph.gaps`; `structuredEvidenceCompleteness` | — |
| история изменений | `DocumentRecord.history` (версии документа) | ★ `artifact.history[]` — append-only `{at, actor, from, to, reason}`, не больше 50 записей (как TeamHarness) |
| условия актуальности | `freshnessPolicy` источника, `REUSE_MS`, `dueForReverification` | ★ `artifact.revalidateWhen`: отпечаток источника изменился, вышла новая редакция, изменились ограничения врача, истёк срок |
| причина отказа или замены | — | ★ `artifact.statusReason` |

Типизированное содержимое у каждого вида своё, без бессмысленных общих полей:

- **`study_appraisal`** — разбор исследования. Идентификатор (PMID / DOI), версия текста (аннотация или полный текст + отпечаток), поля из `research-structured-evidence` (популяция, вмешательство, сравнение, конечная точка, эффект) с якорем-цитатой, результаты проверок по каждому полю.
- **`search_outcome`** — отрицательный или пустой результат. Где искали (источник + запрос), когда, сколько нашли, причина (пусто / источник недоступен / исключён врачом), срок жизни.
- **Существующие** — `drug_comparison`, `guideline_check`, `source_positions` — остаются графом и манифестом прогона. Конверт им нужен, только когда их начнут наследовать.

Правило передачи: **использование артефакта другим этапом не повышает его статус.** Статус меняет только проверка из раздела 5. Происхождение и статус переносятся в производный результат без изменений.

### 4.2 Граф исполнения разбора исследования

Небольшой типизированный граф поверх текущей оркестрации, без универсального workflow engine:

```
запрос врача
  └─ S1 идентификация первоисточника   (PMID/DOI/название → PubMed)                 → study_ref
       └─ S2 получение текста           (аннотация / полный текст PMC, отпечаток)    → study_text
            ├─ S3 извлечение полей      (research-structured-evidence)               → study_appraisal (draft)
            └─ S3' соответствие вопросу (популяция и вмешательство vs вопрос)        → relevance
                 └─ S4 проверка          (детерминированные проверки, раздел 5)      → study_appraisal (verified | rejected)
                      └─ S5 сборка ответа (манифест с цитатами и статусами)          → результат прогона
                           └─ S6 «Сохранить» → Material (sourceResultId → артефакт)
```

- Этап хранится как расширенный `PlanStep`: уже есть `id`, `label`, `tool`, `status`, `detail`, `connectorIds`; добавляются ★ `inputs[]` / `outputs[]` (id артефактов) и ★ `attempt`.
- **Повтор только упавшего этапа.** Если S2 не получил текст (PubMed недоступен), повторяется S2 с тем же `study_ref`. S1 заново не идёт. Механика повторов уже есть в планировщике: ограниченное число попыток с задержкой.
- **Продолжение после перезапуска.** Этапы с `outputs` в хранилище не перезапускаются. Это та же идея, что журнал слотов фоновых проверок.
- **Лимиты.** Дедлайн прогона и бюджеты источников уже есть. Незавершённый этап отображается как незавершённый: «частично» с названной причиной, а не пустой ответ.
- **Параллельность.** S3 и S3' независимы.

## 5. Правила независимой проверки и повторного использования

### 5.1 Проверка — детерминированная там, где это возможно

| Что проверяем | Чем | Есть сейчас |
| --- | --- | --- |
| Цитата соответствует источнику | Поиск фрагмента в тексте чанка (статус SUPPORTED / PARTIALLY_SUPPORTED / UNKNOWN / UNSUPPORTED) | да |
| Числа и вычисления | Разбор чисел из цитаты; ДИ содержит точечную оценку; единицы указаны; пересчёт NNT/ARR из исходных долей, когда они есть; для калькуляторов — пересчитанные примеры | калькуляторы — да; числа исследований — ★ |
| Релевантность вопросу | Совпадение популяции и вмешательства с условиями вопроса («Искали по» / «Не учтено» — `lib/portal/unmatched.ts`) | да, как предупреждение; на артефакте — ★ |
| Нужная редакция документа | Отпечаток версии и дата; `currentness` (EX-06) | да |
| Ограничения врача по источникам | Исключённые источники не вызываются, а их журналы скрываются (PR #27); снимок ограничений на артефакте сверяется при повторном использовании | вызов — да; сверка при повторе — ★ |
| Исполнение инструментов | `toolsUsed[]` со статусом; молчавший источник не даёт повторного использования | да |
| Нет смешивания пользователей и задач | `sessionId` на каждой записи; ключ повторного использования включает то, что ищут источники (PR #28); тесты изоляции | да |
| Контракты результата | Zod-схема манифеста, политики EX / Source / DS, корпус маршрутов | да |
| Разрешение ссылок | HEAD-запрос к ссылке источника | ★ (в песочнице нет сети; выполняется в фоне на сервере) |

Согласие двух LLM медицинское утверждение не доказывает. В продукте LLM-критика нет, и он не вводится. Независимость обеспечивают три ревьюера разработки (A, B, C), которые получают первоисточник, код и экран, а не пересказ автора.

### 5.2 Наследование результата: условия

Ранее полученный артефакт используется в новой задаче, только если выполнены **все** условия, и каждое проверяется детерминированно:

1. Тот же владелец (`sessionId`) или артефакт из публичного источника, без данных врача.
2. Статус `verified`, а не `rejected`, `stale` или `superseded`.
3. Отпечаток первоисточника совпадает с текущим. Новая редакция или полный текст вместо аннотации — повод перепроверить, а не наследовать.
4. Ограничения врача не стали строже: исключённый с тех пор источник делает артефакт неприменимым.
5. Артефакт относится к новому вопросу: тот же идентификатор исследования, а популяция и вмешательство вопроса покрыты полями артефакта.
6. Это не дубликат: один первоисточник в разных копиях считается одним (ключ — PMID/DOI).

Исходный материал, интерпретация и выводы хранятся раздельно: текст источника (чанк) → извлечённое поле с якорем-цитатой → утверждение на экране. Если поле позже признано ошибочным (`rejected`), производные результаты получают статус `stale` с причиной, и ошибка дальше не идёт. Обход производных уже реализован для документов (`knowledge.dependents`).

Отрицательные результаты (`search_outcome`) сохраняются с коротким сроком жизни. Они не мешают повторной проверке, когда источник снова доступен или изменился запрос. Гипотезы в доверенную память не попадают: черновик (`draft`) не наследуется никогда.

## 6. Риски, стоимость, внешние зависимости

- **Внедряемое не добавляет зависимостей.** Всё строится на PostgreSQL, Drizzle и существующих адаптерах. Новых сервисов, очередей и LLM нет.
- **Отклонённые зависимости:**
  - Matrix, MinIO, Kubernetes (AgentTeams);
  - платный ключ Edison (Robin);
  - EVM-кошелёк и публичный IPFS — промпты публичны, для медицинских материалов недопустимо (Olas);
  - AGPL-3.0 (Buttercup) — механизм берём как идею, код не переносим;
  - репозиторий AgentNet без лицензии — нельзя переносить даже фрагменты.
- **Риск распространения ошибки** — главный риск памяти (AgentRxiv, §4.1 статьи). Меры: статус `verified` только после детерминированной проверки, `rejected` и `stale` распространяются на производные, запрет наследовать черновики.
- **Риск Goodhart** (OpenEvolve, MLX). Проверка не должна стать целью. Регрессионные тесты и корпус маршрутов проверяются ревьюерами, а не только зелёным статусом.
- **Стоимость.** Хранение артефакта разбора — одна строка в `agent_results` с атрибутами. Экономия — повторные запросы к PubMed и PMC для того же исследования. Деньги сегодня не измеряются (нет платных API), поэтому метрики — время и число повторно использованных валидных артефактов.

## 8. Следующее минимальное изменение и критерии приёмки

**Изменение: «Разбор исследования с наследованием проверенного артефакта».** Это эксперимент для проверки архитектуры, а не новая большая функция.

1. `study_appraisal` как `AgentResult` (kind `research_finding`) с конвертом в `attributes`: `artifact.kind`, `artifact.version`, `artifact.status`, `artifact.sourceFingerprints`, `artifact.constraints`, `artifact.verifiedAt`, `artifact.parents`, `artifact.history`. Новых таблиц нет.
2. Детерминированная проверка S4: якорь-цитата каждого поля найдена в тексте; ДИ содержит точечную оценку; единицы указаны. Иначе поле `UNKNOWN`, а артефакт `draft` → `rejected` с причиной.
3. При разборе по PMID/DOI сначала ищется артефакт по условиям 5.2. Если он применим — используется повторно, а в «Ход работы» пишется: «использован разбор от <дата>, текст источника не изменился». Если нет — этапы S2–S4 выполняются заново, причина видна.
4. «Сохранить» связывает `Material.sourceResultId` с артефактом. Отклонённый позже артефакт помечает сохранённый материал «требует сверки».

Критерии приёмки — каждый проверяется тестом:

- Повторный вопрос о том же PMID в той же сессии использует артефакт: 0 запросов к PubMed / PMC (счётчики фейковых адаптеров) и запись в ходе работы.
- Другая сессия артефакт не видит (тест изоляции).
- Изменённый отпечаток текста (аннотация → полный текст) запускает S2–S4, а не повторное использование.
- Источник, исключённый после создания артефакта, делает его неприменимым.
- Поле с ДИ, не содержащим точечную оценку, получает `UNKNOWN`, а артефакт не становится `verified`.
- Отклонение артефакта переводит производный сохранённый материал в «требует сверки».
- Корпус маршрутов: 0 изменений маршрутов; регрессионный набор раундов зелёный.

Метрики: доля повторно использованных **валидных** артефактов, ноль ложных повторных использований (по тестам выше), время ответа на повторный вопрос, число запросов к внешним источникам. Деньги не измеряются: платных API нет. Количество агентов, сообщений и размер памяти не оптимизируются.

**Статус:** не реализовано. Реализация — после ревью релиза R1 и исправления его P0/P1, отдельным срезом с тем же гейтом.
