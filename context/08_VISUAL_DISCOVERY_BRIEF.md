# Visual Discovery Brief

## Problem

We do not yet know what the application should look like.

Therefore Claude must not prematurely optimize one arbitrary first rendering.

The Phase 1 task is to discover a **visual operating model** that makes dense clinical information fast, calm, trustworthy, and actionable.

## Desired qualities

The interface should feel:

- clinically serious without looking like legacy hospital software;
- information-dense without becoming noisy;
- calm under time pressure;
- precise;
- source-aware;
- longitudinal;
- action-oriented;
- native to a modern professional tool;
- legible from a laptop in a clinic;
- still usable on tablet and phone.

## Not desired

Avoid:
- generic AI SaaS dashboard;
- purple gradient / neon AI aesthetic;
- glassmorphism;
- excessive floating cards;
- huge marketing-style whitespace;
- chatbot-first information architecture;
- rounded-card soup;
- decorative health illustrations;
- "friendly wellness app" tone;
- consumer fitness aesthetic;
- fake futuristic diagnostic UI;
- visual noise from every abnormal value becoming red.

## Content density rule

Do not equate "premium" with "empty".

Clinical premium = hierarchy + precision + speed.

## Visual exploration method

Create **3 materially different concepts**.

All concepts must use:
- the same mock data;
- the same four core workflow moments;
- the same source-derived safety rules.

This prevents content differences from biasing visual evaluation.

## Required comparison scenes

Every concept must render the same scenes:

### Scene A — Morning queue
Question:
"Who needs my attention first?"

### Scene B — Pre-visit patient brief
Question:
"What changed and what must I resolve?"

### Scene C — In-visit workspace
Question:
"What should I capture/clarify/verify without disrupting the visit?"

### Scene D — Post-visit task closure
Question:
"Is the plan complete, reviewed, assigned, and safely executable?"

### Optional Scene E — Between visits
Question:
"Who needs attention today based on trajectory, not raw alert count?"

## Each concept must specify

- visual thesis;
- information hierarchy;
- navigation model;
- density strategy;
- use of color;
- typography strategy;
- provenance pattern;
- AI presence pattern;
- interaction model;
- desktop behavior;
- tablet behavior;
- phone behavior;
- strongest advantage;
- biggest risk.

## Do not make cosmetic variants

Not acceptable:
- Concept A blue
- Concept B green
- Concept C dark

Concepts must differ structurally.

## Before user selection

Do NOT:
- create final `design.md`;
- build a large component library;
- polish all micro-interactions;
- choose a final brand palette;
- build production integrations.

Phase 1 is for comparing systems.
